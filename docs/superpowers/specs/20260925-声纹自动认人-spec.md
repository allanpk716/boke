# Spec:声纹自动认人(voiceid)— 2026-09-25

> 来源:设计共识(两轮结构化问答)+ 异构评审两轮(2026-09-25,评审记录见 .xcheck,不入库)。术语遵守 CONTEXT.md(声纹档案/声纹建议/参考音用途标记/核对门/主持人/合并)。

## Problem Statement(用户视角)

核对门目前靠人工指认"这个说话人是谁、主持人是谁"。博主和常客嘉宾反复出现,每期都要重新指认一遍;人物越多越费眼。希望:标记过的人物声音积累起来后,新视频自动认出每个说话人最像谁、是不是博主本人,人工只需确认或修改。

## Solution(用户视角)

1. 分人跑完,每个说话人自动与人物库声纹档案比对,核对门卡片上显示"声纹建议:圆脸 0.72"。
2. 建议可信时(分数过阈值且明显领先第二名)自动预填说话人→人物、以及主持人(匹配博主且过更严阈值);永远只预填,提交仍由人工点。
3. 两个人争同一个人物时,落选方显示"竞争"提示——常提示分身,引导合并。
4. 档案样本不够、阈值没校准的时期(冷启动),只显示分数、不预填,攒够自动升级。
5. 核对门提交后,本期确认的说话人样本自动进入该人物的声纹档案(按语言分组),并回显"已归档 N 条";与已有档案明显不符的条目拦下来,可试听、可强制入库。
6. 阈值随档案自动校准,人物库详情页可试听/删除档案条目。

## User Stories

1. 作为用户,我想要每个说话人卡片显示声纹建议(最像的人物+分数),以便不用逐个凭听觉认人。
2. 作为用户,我想要建议可信时自动预填说话人→人物下拉,以便少点几次。
3. 作为用户,我想要匹配博主且分数足够高时自动预填主持人(host+host_person),以便省掉每期指认主持人这一步。
4. 作为用户,我想要两个说话人争同一人物时看到竞争提示,以便发现该合并的分身。
5. 作为用户,我想要冷启动期只看分数不被瞎预填,以便不产生错误信心;攒够样本自动升级。
6. 作为用户,我想要核对门提交后样本自动归档并回显条数,以便档案零维护地长大。
7. 作为用户,我想要与已有档案对不上的新样本被拦下(可试听、可"仍入库"),以便一次手滑不污染档案。
8. 作为用户,我想要档案按语言分组、跨语言不混,以便中文参考音和英文参考音各司其职。
9. 作为用户,我想要测试说话人语言与档案语言不匹配时仍给跨语言参考分数(用更严阈值),以便信息不静默消失。
10. 作为用户,我想要人物库详情页列出档案条目(试听/删除/来源/用途),以便排查坏样本。
11. 作为用户,我想要克隆选音界面默认只列克隆用途的参考音,以便自动归档样本不干扰选音。
12. 作为用户,我想要桩数据分 P 显示"声纹建议不可用(分人为桩数据)",以便不困惑这期为什么没建议。
13. 作为用户,我想要阈值随归档自动重算并显示样本数,以便知道系统什么时候"学会了"。
14. 作为用户,我想要参考音删除/人物删除时关联向量与自动样本被级联清理,以便不留垃圾。

## Implementation Decisions

**技术路线**(细节以评审定稿 R1 为准,此处列契约):
- 向量来源:分人管线输出 `DiarizeOutput.speaker_embeddings`(num_speakers×256,与 rttm SPK 标签顺序对齐)由 diar_run.py 落盘(spk_emb.npy + 标签顺序 json);mock/桩分 P 无 embedding → 无建议。
- **[F2 解除裁定] 档案向量 = 由存储的 ≤30s 样本片段直接抽取的 embedding**(同一模型:community-1 内置 WeSpeaker ResNet34),不是整期分人质心——这是 D2"音频片段+派生向量"的已确认语义;分人质心仅用于当期建议计算。票验收必须含"缓存向量与样本同模型重算 cos≥0.999"断言。
- 识别:每说话人向量 × 人物档案逐条 cosine → 分数层平均;语言路由(同语言组优先;无同语言组:单组用该组/多组取最高组均值;均按跨语言档阈值);双门(score≥THR 且 margin≥MARGIN);一对一互斥(贪心最高分配对,落选方 verdict=compete)。
- 校准(每次归档后自动重算,落 work/voiceid_thresholds.json,记样本数):同人分布=留一法;冒认分布=跨人物交叉对(含跨语言交叉对);解锁双条件=同人样本≥5 且冒认对≥10,任一不足该语言对 uncalibrated 不预填;THR=冒认 p99(冒认<20:max(p99,max+0.02));MARGIN=同人 top1−top2 差 p5(下限 0.03);跨语言档=该方向≥10 跨语言冒认对用专属分布 p99,否则同语言档 THR+0.05;THR_host=max(THR+0.05,同人分布 p25),未校准不预填主持人;输出 EER。
- **[F5 机械默认]** 一致性检查:该人物该语言组条目 <2 条时跳过检查直接入库。
- **[F6 机械默认]** 冷启动只关预填:徽章分数与竞争提示照常显示。
- 存储:persons.json refs[] = 参考音唯一清单,新增可选 use(clone|voiceid,旧条目缺省 clone,向后兼容);自动归档条目 use=voiceid 入 refs[](path 指向样本切片);向量缓存 work/persons_emb.json(person,lang,vec,ref_path,bvid,part,spk,ts,model),ref_path 为关联键;删除 refs 条目/人物 → 级联删向量记录与自动样本文件(手动上传只删缓存不删用户原文件);persons.json 不存向量。
- 归档钩子:api_review 提交成功分支,按最终说话人集合逐 SPK 切 ≤30s 样本(cut_speaker_samples 复用)+抽取向量+一致性检查+校准重算+toast 回显实际条数;合并分身后同人物多 SPK 各自成条(打分层聚合)。
- 计算时机:分人完成自动识别落 work/<id>/voiceid.json(verdict:suggest/unknown/compete/uncalibrated+主持人候选);打开核对门时档案比结果新则重算。
- UI:review.html 徽章/预选/主持人预填/竞争/冷启动/桩模式小字;克隆选音默认过滤 use≠clone(并审计 refs[] 既有读取点的 use 过滤)。
- 不做:音色预挂、已核对视频追溯、商业 API、分人算法改动、CAM++ 切换(后续独立决策)。

## Testing Decisions

- 单元测试为主(pytest,tests/ 目录,沿用仓库先例);voiceid 核心逻辑(路由/双门/互斥/竞争/冷启动/校准统计)为纯函数,用合成向量测试,不依赖 pyannote。
- 票:embedding 落盘 — stub DiarizeOutput 单测(形状/顺序);**对齐断言**(F8):提供 GPU 环境可跑的校验命令,验收时对至少一个真实 episode 核 spk_emb.npy 行序=rtm SPK 顺序。
- 票:归档 — **重算一致性断言**(F2 解除):同模型重抽样本 embedding 与缓存向量 cos≥0.999(测试用 stub 模型注入,真实 GPU 跑法随票给)。
- Web 层沿用现有 web_server 测试先例(API 合约+busy/围栏不回归);UI 验收以 API 字段+页面渲染 smoke 为准。
- 全量 pytest 保持绿(零回归)。
