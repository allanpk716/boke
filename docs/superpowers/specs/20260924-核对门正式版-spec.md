# 核对门正式版:核对决策落地 / 小样生成 / 片库状态机 — Spec

- 日期:2026-09-24
- 来源:夜链评审链 round 1 快照(`.xcheck/20260924-165113/proposal.md`)+ D/F 记录;决策约束以该环 decisions.md 为准(D1–D14,U1–U4)
- 术语:遵循 `CONTEXT.md` 词汇表(分P/主持人/人物库/核对门/合并/小样/片库/导入)

## Problem Statement

用户(博主内容的订阅者)要把博主的外语采访视频转成中文配音音频。管道六段(抽音轨/OCR 字幕/声纹分人/归人/合成/混音)与三个 mock 页面(片库/核对台/试听台)已存在并验证,但从"核对台提交核对"到"成品上试听台"之间的一切仍靠人工:核对决策靠人工翻译成音色配置、小样不存在、片库状态是手写死数据。本规格把这段自动化。

## Solution(用户视角)

用户在片库勾选或粘贴 BV 号导入视频 → 系统自动下载并分析(OCR/分人/语言检测) → 片库出现"待核对" → 用户在核对台边看视频边核对说话人(试听样本、指认主持人、合并分身、给每人配声音)、确认或否决"全中文跳过" → 提交 → 系统自动出 1–2 分钟小样 → 用户听过点"过" → 系统自动跑全片合成 → 成品出现在试听台。任何阶段失败,片库显示失败态并可一键重试;改决策重出小样时,旧产物自动作废不会串味。

## User Stories

1. 作为用户,我想要在片库页粘贴 BV 号导入单个视频,以便快速处理某一期。
2. 作为用户,我想要在片库页按播主清单(含专属/采访筛选)勾选批量导入,以便批量处理。
3. 作为用户,我想要导入前系统自动校验 B 站 cookie 并在失效时红条提示暂停,以便不会产生半拉子下载。
4. 作为用户,我想要下载完成后系统自动跑分析并把状态推进到"待核对",以便无需命令行。
5. 作为用户,我想要分析失败时看到失败态与错误信息并能点"重试"断点续跑,以便不整期报废。
6. 作为用户,我想要在核对台内嵌播放器里看原片,以便边看边核对说话人。
7. 作为用户,我想要每张说话人卡能听原声样本、填备注名(纯注释)、合并分身、三选声音(克隆/预设/跳过),以便一次核对完成所有决策。
8. 作为用户,我想要点"设为主持人"后从人物库选人挂接音色,以便主持人用库里的参考音克隆。
9. 作为用户,我想要"存入人物库"弹窗(参考音候选试听选一、已有人物或新建、主要语言预填、备注),以便常客嘉宾一次收录全局复用。
10. 作为用户,我想要全中文分P由系统建议跳过并由我确认,以便不错杀也不白做。
11. 作为用户,我想要提交核对后自动收到小样(片头60s+对话密集处60s,用最终音色),以便花 2 分钟拦住"只有耳朵能发现的问题"。
12. 作为用户,我想要点小样"不过"回到核对台改决策并重出小样,以便不浪费 40 分钟全片 GPU。
13. 作为用户,我想要点小样"过"后系统自动全片合成、完成后成品挂试听台,以便全程无命令行。
14. 作为用户,我想要合成进行中看到"合成中"状态,以便知道系统没死。
15. 作为用户,我想要改决策重出小样时旧产物自动作废,以便新小样一定反映最新决策。
16. 作为用户,我想要重跑分人后既有说话人决策清空重来,以便不会错配到新标签。
17. 作为用户,我想要三个页面显示同一状态源的同一期名/状态,以便不被两套数据搞晕。

## Implementation Decisions

- **片库账本**:单 JSON 文件(`work/library.json`)为唯一状态源;每视频每分P一条记录(bvid/标题/日期/时长/专属标记/媒体文件路径/状态+busy/各阶段产物路径/核对决策/小样路径含作废标记/成品路径/错误信息)。**单写入者**:所有状态变更经账本模块的串行接口(进程内锁+原子写:写临时文件后 rename),后台任务完成回调与页面操作同走该接口。
- **状态机**:主链七态(待下载→待分析→待核对→已核对待合成→小样待听→全片合成中→已交付)+旁路两态(已排除/失败);各主态附 busy 子标志;转移规则照 proposal rev1 §2 M3(含小样不过回退边、失败重试断点重入、改人数重跑分人决策作废)。
- **人物库**(`work/persons.json` 同款原子写):人物={备注名,主要语言,头像(可选文件引用),备注,refs:[{audio,transcript,lang,source(期/分P/说话人|手动上传)}]};初始种子=圆脸(refs/yuanlian_chinese_01/02+ref01_transcript.txt)+小外(英文参考音)。
- **主持人挂接校验**:所选人物必须存在"参考音+配套转写稿"齐备条目,且参考音来源分P ≠ 当前分P;不满足在提交核对前阻断并明示缺项,不静默降级。
- **核对决策 JSON**(每分P):{verdict: dub|skip, speakers:[{id, note, host, host_person, merge_into, voice: clone|preset|skip, preset_voice, clone_ref}], rediarize?: {max_speakers}}。
- **决策版本与缓存失效(F12 解除条件)**:提交核对时对决策 JSON 计算内容哈希 `dec_hash`;该分P全部下游产物(voices.generated.yaml/合成单元 wav/小样/成品)落 `work/<id>/dec_<hash>/` 目录或文件名携带 hash;`dec_hash` 变化 ⇒ 新键,旧产物自然失效(保留可查但不再引用);断点重试仅在**同一 dec_hash 目录内**按"产物存在且完整(以 .done 哨兵文件标记,写入完成后才创建)"复用;半写入文件无哨兵即视为不存在。
- **决策应用器**:合并 → rttm 标签合并 → 重跑 attribute;rediarize → 决策作废回待核对;生成 `work/<id>/dec_<hash>/voices.generated.yaml`(格式同现有 voices.yaml 的 episode_maps,由 synthesize 读取);旧 `src/boke/voices.yaml` 只读兜底不变。
- **嘉宾克隆** = CosyVoice3 cross 无文本模式(引擎已落地);候选=本人本期外语原声干净段;主持人 = zero 模式(人物库参考音+转写稿)。跳过 = 该说话人片段在混音时保留原声(假设 U4,小样如实呈现)。
- **小样生成**:片头 60s + 密集窗(默认=归人结果字幕条数/分钟最高 60s,排除片头 90s/片尾 60s;不足时放宽排除边界,仍无则取中点 60s)——固定两段,复用决策应用器+现有 synthesize/mix 在 dec_<hash> 目录内产出 2 段并拼挂核对台。
- **导入**:BV 粘贴与清单勾选两入口;导入前 cookie 预检(拉取播主 nav 接口验证 SESSDATA),失败红条暂停;清单数据源=既有 `work/space_videos.json` 拉取工具。
- **页面真实化**:三个页面改为请求账本/人物库/决策接口渲染(保留现有静态 mock 结构,替换数据源与提交动作);期名/状态/跳过判定/小样/重试按钮全部来自账本;视频与音频文件经既有 /media /audio 路由。
- **分析编排**:下载完成事件→依次 extract→ocr→diarize(隔离 venv 经现有 subprocess runner)→attribute→check_language→产物路径入账→待核对;任一步异常→失败态+错误信息。

## Testing Decisions

- 账本状态机:纯函数转移表单测(全部合法/非法转移、busy/失败/重试/回退边、改人数重跑作废)。
- 决策版本:单测——同决策重试复用哨兵产物;决策变更产生新 hash 且旧产物不再被引用;半写入(无哨兵)不复用。
- 人物库校验:单测——缺转写稿阻断、同分P参考音拒绝、种子初始化幂等。
- 决策应用器:沿用 tests/ 既有 pytest 风格;合并后归人重算用构造 rttm/srt 验证。
- 端到端:验收脚本按 spec 验收 6 条逐条冒烟(真实媒体可选跑)。
- 仓库既有 tests/test_attribute.py 8 用例必须保持绿(零回归)。

## Out of Scope

订阅自动发现/定时下载、Nemotron-3-Diarization 评估、声纹自动认人、视频成品、BGM 垫底、翻译、多用户鉴权、头像上传交互(仅存储引用与占位展示)。
