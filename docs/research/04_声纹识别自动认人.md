## ② 技术路线：分人之后怎么"认人"

### 2.1 标准两段式：辨认（1:N）+ 确认（1:1）

声纹识别分两个问题，术语对应关系：

- **说话人辨认（identification, 1:N）**：这段音是谁——拿测试 embedding 和库里 N 个人的注册 embedding 逐一算 cosine，取最高分者；
- **说话人确认（verification, 1:1）**：这个人是不是 X——测试 embedding 和 X 的注册 embedding 算一个分，过阈值才算"是"。

两者用的是**同一个 embedding 模型 + cosine 相似度**，差别只在判读方式（argmax vs 单阈值）。所以工程上就是一件事：**每个分人说话人抽一个 embedding，人物库每人存若干注册 embedding，做相似度矩阵，按阈值+margin 出建议**。本项目"把每个说话人识别成人物库里的谁"是辨认，"是不是博主本人"是对"圆脸"这一个人的确认，一次矩阵计算两个都覆盖。

### 2.2 pyannote.audio 官方支持度查证（2026-09-25，逐条源码/issue 为准）

**版本现状**：PyPI 最新 `pyannote.audio` **4.0.7**（2026-06-30 发版，[PyPI](https://pypi.org/pypi/pyannote.audio/json)；GitHub 仓库最后 push 2026-09-24，活跃）。`pyannote/speaker-diarization-community-1` 的 config.yaml 声明依赖 `pyannote.audio: 4.0.0`（本机 HF 缓存里该文件实测），与 `src/boke/diarize.py` 里"community-1 要求 pyannote>=4"的注释一致。注意 `pyproject.toml` 的 diar extra 还写着 `pyannote.audio>=3.3`，实际应视为 `>=4.0`（community-1 在 3.3.2 上会报 'plda' 参数错，diarize.py 注释已记录）。

**查证 1：管线不支持传入参考音频/参考 embedding 自动命名。** 读 4.x `SpeakerDiarization` 管线源码（[speaker_diarization.py @ main](https://github.com/pyannote/pyannote-audio/blob/main/src/pyannote/audio/pipelines/speaker_diarization.py)）：运行时参数只有 `num_speakers / min_speakers / max_speakers / hook`；构造超参只有 `segmentation / embedding / plda / clustering / batch_size` 等。源码里出现的 "reference" 一词全部是**评测用途**（传入 ground-truth 标注做 DER 的最优标签映射），不是注册认人。没有任何 `identify` / `enroll` / `voiceprint` 逻辑。

**查证 2：官方明确答复"还没有"。** issue [#1369 "How can I identify speaker names from voiceprints?"](https://github.com/pyannote/pyannote-audio/issues/1369)，维护者 hbredin 答复原文："**Not yet.** But there is an ongoing PR getting us closer to this feature: #1346"。issue [#1383 "Speaker reidentification"](https://github.com/pyannote/pyannote-audio/issues/1383) 中 hbredin 称这是 "recurrent request"，并指向同一 PR 作为起点。截至 4.0.7 仍未内置。

**查证 3：那个 PR（#1346，2023-06-23 合并）给出的官方替代品——管线直接吐出每个说话人的 embedding。** [PR #1346](https://github.com/pyannote/pyannote-audio/pull/1346) 让 diarization 输出携带 per-speaker embedding。4.x 里体现为 `DiarizeOutput.speaker_embeddings`：形状 `(num_speakers, dim)`，**是聚类质心，且顺序与 `speaker_diarization.labels()` 对齐**（源码 apply() 末尾显式重排：`centroids = centroids[[inverse_mapping[label] ...]]`）。也就是说：**认人所需的"每个说话人一个向量"，pyannote 已经白送，不必自己重抽**。

**查证 4：community-1 内部用什么 embedding。** 本机 HF 缓存 checkpoint 实测（`models--pyannote--speaker-diarization-community-1/snapshots/.../embedding/pytorch_model.bin`）：架构为 `pyannote.audio.models.embedding.wespeaker.WeSpeakerResNet34`，输出 **256 维**（seg_1 层 5120→256），输入按 **5 秒**窗切，`embedding_exclude_overlap: true`（重叠段不参与质心）。即 pyannote 官方把 WeSpeaker 的 ResNet34 封装训练后内置在管线里。pyannote 另有独立模型 [`pyannote/wespeaker-voxceleb-resnet34-LM`](https://huggingface.co/pyannote/wespeaker-voxceleb-resnet34-LM)（VoxCeleb 训练，CC-BY-4.0），是官方文档推荐的单独抽 embedding 用法（`Inference(model, window="whole")`，模型卡有完整示例代码）。**能否直接复用管线内 embedding 做 1:1 比对：可以**——它就是标准的 WeSpeaker ResNet34 嵌入空间，cosine 比对即可；但注册音（中文）与测试段（英文）跨语言时的分离度要实测（见 §③.2）。

**查证 5：商业版有、开源版没有。** pyannote.ai 付费 API 提供 [voiceprint + identify 端点](https://docs.pyannote.ai/tutorials/identification-with-voiceprints.md)：注册音**最长 30 秒**、每人一条 voiceprint、可复用；identify 支持逐条 `matching.threshold`（官方建议 50-70）和 `matching.exclusive`（默认 true，防止多个说话人配到同一个人）；官方并明说"**voiceprint 仍可能匹配到并不在录音里的人**，要调阈值"。这套语义（置信度+阈值+exclusive+人工可改）就是本项目核对门建议的参照原型。本项目自用、且音频不宜上传第三方，**不采用付费 API，只借鉴其交互语义**。

### 2.3 本项目路线图（结论）

```
diarization(已有) ──► 每说话人 embedding(管线白送/自抽) ──► cosine × 人物库注册embedding
                                                              │
                              建议 person + score + margin ◄──┘
                                        │
                     核对门 UI 预填(主持人=圆脸/说话人→人物)，人工改/确认(不变)
                                        │
              确认后的候选原声段经 /api/persons/ref 存入人物库(已有) → 注册embedding缓存更新
```

### 3.2 跨语言是本项目的主战场（有硬数字的域差证据）

我们的场景天然跨语言：**参考音取自博主中文视频（CONTEXT.md：中文参考音 10s~1min），测试段是英文采访**。说话人 embedding 理论上语言无关，但训练域差会真实掉分：

- **英文训练模型在中文野数据上约掉 4 倍**：CN-Celeb 官方论文（[arXiv:2012.12468](https://arxiv.org/abs/2012.12468)）原文：用 VoxCeleb 训练的系统在 SITW（英文）EER 3.75%，在 CN-Celeb.E（中文子集）**15.52%，恶化 300%**。这是 x-vector 时代的基线，新模型+增广会收窄，但方向成立：**英文域模型（pyannote 内置/ECAPA/TitaNet）直接跨到中文域，风险最高**；
- **中文大数据训练能压下来**：CAM++ 同架构在 CN-Celeb 上 6.78%（~3k 说话人）→ **4.32%**（20 万说话人，官方模型卡），说明训练数据规模与域覆盖比架构更关键；
- **WeSpeaker 的 LM 后缀说明**（[官方 pretrained.md](https://github.com/wenet-e2e/wespeaker/blob/master/docs/pretrained.md) 原文）："LM 表示用 large-margin fine-tune，**对 >3s 的长音频表现更好**"——对本项目注册音（10~25s）正好是加分项。

**结论**：起步用 community-1 内置 embedding（零成本、同管线、注册与测试同一嵌入空间），**立刻用 §⑥ 实验量"中文注册→英文测试"的实际分离度**；不够再上 CAM++ 中文通用版（CN-Celeb 4.32% 是所有候选里最好的中文硬数字，且 20 万说话人的多域训练对跨语言最友好）。选型裁决权交给实验数据，不预支结论。

### 3.3 落选理由速记

- **SpeechBrain ECAPA**：数字好（0.80%）但英文域训练，跨中文无优势，作为"换个模型重跑实验"的第二对照合适，不作主力；
- **NeMo TitaNet**：英文数据训练（模型卡自述），引入 NeMo 全家桶代价高，中文无硬数字——不选；
- **resemblyzer**：无基准、英文自述、仓库停滞——避开；
- **WavLM-base-plus-sv**：模型卡无 EER 基准（仅 transformers 示例阈值 ~0.86），X-vector 头微调口径与主流 SV 差异大——不作候选。

## ④ 比对与阈值策略

### 4.1 官方默认阈值盘点（结论：无通用值，必须自校准）

| 来源 | 默认值 | 口径说明 |
|---|---|---|
| CAM++ 中文通用（ModelScope 卡） | **thr=0.31** | cosine；官方在线体验与 `sv_pipeline(..., thr=0.31)` 示例同值（[模型卡](https://modelscope.cn/models/iic/speech_campplus_sv_zh-cn_16k-common)） |
| SpeechBrain ECAPA `verify_batch` | **threshold=0.25** | cosine，[源码](https://github.com/speechbrain/speechbrain/blob/main/speechbrain/inference/speaker.py) `def verify_batch(..., threshold=0.25)` |
| wespeaker CLI | **无阈值** | `recognize` 永远返回最高分者；且其"confidence"做了 (cos+1)/2 重映射到 [0,1]（[源码](https://github.com/wenet-e2e/wespeaker/blob/master/wespeaker/cli/speaker.py)）——**引用别人 wespeaker 分数时先确认有没有被重映射** |
| pyannote.ai identify（商业参照） | 默认 0，建议 **50-70**（0-100 置信度） | 官方教程明说会误配到不在录音里的人 |
| pyannote 开源 | 无认人功能，无阈值 | §②查证 |

### 4.2 多段聚合：先平均 embedding，还是逐段打分再平均？

两种都是业界常规，本项目的数据形态下建议**分数层平均**：

- 注册侧：人物每条 ref 各抽一个 embedding（wespeaker CLI 对整条音频单次前向即出一个向量，[源码](https://github.com/wenet-e2e/wespeaker/blob/master/wespeaker/cli/speaker.py)），**保留多条**；pyannote 管线内部（community-1 质心 = 5s 窗 embedding 聚类中心，本地 checkpoint 实测 `duration=5.0`）是"embedding 层平均"的代表；
- 打分侧：`score(SPK, person) = mean_k cosine(spk_emb, ref_k)`，多条 ref 逐条打分再平均（**按语言分组路由，见 §4.6**）。好处：单条坏 ref（BGM 重、太短）不会污染整人质心，还能顺手输出"哪条 ref 最像"辅助人工排查；
- 测试侧：**用管线给的 SPK 质心**（整期所有段的聚合，等效 embedding 层平均），不要用单段 embedding 打分——单段短、噪声大。

### 4.3 注册音/测试段时长

- **注册音**：社区参照 10~15 秒连续语音即够（[pyannote issue #1369 评论区实践](https://github.com/pyannote/pyannote-audio/issues/1369)）；商业参照上限 30 秒/条（pyannote.ai 官方）；本项目已有 ref 为 10~25s（refs/yuanlian_chinese_01/02.wav），够用；多条 ref 优于单条长 ref；
- **测试段**：单段 ≥3s（WeSpeaker 官方 LM 说明的适用下界；pyannote 也有[短音频抽不出有效 embedding 的 issue #1961](https://github.com/pyannote/pyannote-audio/issues/1961)）；本项目打分对象是**整期 SPK 质心**（等效几十段聚合），天然规避短段问题；仅"逐段打分"模式要过滤 <3s 段。

### 4.4 "未知说话人"拒识：argmax + margin

- 判"认识"：`top1_score ≥ THR` 且 `top1_score − top2_score ≥ MARGIN`，两条都过才给建议；任一不过 → 不建议（UI 留空，人工指认，即现状）；
- 判"是博主本人"（对圆脸的 1:1 确认）：`score(SPK, 圆脸) ≥ THR_host`，可用比通用 THR 更高的一档（认错的代价见 §4.5）；
- MARGIN 的意义：人物库人多以后，圆脸和某嘉宾 embedding 偶然都高时靠 margin 分开；pyannote.ai 的 `exclusive=true`（同一 voiceprint 只许配给一个说话人）语义也要抄——**一个 SPK 只建议一个人，一个人物只建议给一个 SPK**（每期取分数最高的配对，贪心一对一）；
- THR/MARGIN 无官方默认，**由 §⑥ 实验的分数分布定**（拟用 impostor 分布 p99 定 THR，margin 取同一批数据 top1-top2 差的分布下界）。

### 4.5 误认/漏认的代价权衡（本项目特有）

- **误认（把嘉宾认成圆脸）代价高**：直接导致主持人音色挂错、克隆源错、成片里嘉宾被圆脸音色配音——交付级事故。且主持人身份决定整个分 P 的处理路径（review_apply.py 的 `host`/`host_person` 校验链）。→ 阈值取保守（偏高），margin 必须开；
- **漏认代价低**：回落到现状（人工在核对门指认），自动认人本来定位就是"建议+人可改"，漏认只是没省到人力，不产生错误。→ 不为召回牺牲精度；
- 一个细节：主持人建议即便置信度高，也**只预填不静默提交**——决策 JSON 仍由人工点"提交"产生（沿用 api_review 现有链路），保证核对门的人工兜底永远在。

### 4.6 人物声纹档案：多条人工确认怎么"综合成一个人"（用户多语言多参考音场景）

> 场景：用户在 N 期视频里人工确认了"这个说话人 = 某人"，且每种语言都会标注若干条参考音。问：第 N+1 期新视频里的声纹，怎么综合判定"是不是这个人"。

**核心认知：每条人工确认同时是三份原料**——①**声纹档案**的存量（每条确认沉淀一个说话人向量）；②**阈值校准样本**（带标签数据，用来量出"同人分数分布 vs 冒认分数分布"）；③**回归测试集**（档案更新后自动重验历史确认）。每新增一条确认，三份同时自动更新——确认数据的价值不止"存了一条音"。

**① 档案结构：按语言分组存向量，不捏成一个死向量**

```
person.圆脸:
  zh: [emb(视频A,SPK_00), emb(视频B,SPK_01), ...]   ← 每条 = 一个向量 + 来源(bvid/part/spk/时长)
  en: [emb(视频C,SPK_00), ...]
  centroid(派生缓存，可随时重算): zh_c = L2norm(mean(zh))，en_c 同理
```

- 不同语言的向量**不互相平均**：跨语言平均会把两个语言域各拉一半，质心两头不靠；按语言分组，判定以逐条打分为准，质心只是可选的加速缓存；
- 旁车文件沿用 §5.2 第 4 条的 `work/persons_emb.json`，每条记录扩 `lang` 字段；每语言每人物封顶（如 10 条，FIFO），防早期坏样本长期占位。

**② 综合判分（新说话人 → 是不是这个人）：语言路由 + 逐条打分 + 平均**

1. **语言路由**：测试说话人的语言管线已有（langid 按说话人判语言）。优先与**同语言**档案比对（域匹配，分数最可信）；该语言档案为空 → 跨语言比对，但换用**跨语言专属阈值**（见③，跨语言的同人/冒认分布整体都偏低且更散，不能共用一个阈值）；
2. **逐条打分再平均**：`score = mean_k cosine(spk_emb, ref_k)`，k 只取所选语言组；保留每条分数，建议里附"最像的是视频C那条（0.81）"辅助人工排查坏 ref；
3. **判定**：`score ≥ THR(该语言对)` 且对第二名人物 `margin ≥ MARGIN` → 出建议；否则留空人工指认。

**③ 阈值从哪来：用已确认数据做留一法（leave-one-out）自校准**

- **同人分布**：对每条已确认 i，用"它 vs 其余 N−1 条建的档案"打分（留一，防止自己给自己抬分）→ N 个诚实的同人分数。10 期确认即得 10 个；若按语言分组（如 6 中 4 英），同语言组、跨语言组各自成分布、各定各的阈值；
- **冒认分布**：所有"人物A的确认 × 人物B的档案"交叉分数（库里有 M 个人即 M(M−1) 组方向）；
- **定值**：`THR = 冒认分布 p99`（样本少时取 max+0.02 余量），按语言对各一份；`MARGIN = 同人组 top1−top2 差的 p5`（下限 0.03）；顺手输出 EER 作档案健康指标；
- **持续重校准**：每新增确认自动重算（脚本即 §⑥ `voiceid_bench.py --recalib`）；阈值落 `work/voiceid_thresholds.json`，记录样本数——某语言对样本 <5 时 UI 标注"阈值未经充分校准"，判定自动降级为纯建议。

**④ 两道保险（防档案被污染/防偶然高分）**

- **入库一致性检查**：新确认的向量入库前，先与该人已有档案打分——低于同人分布 p5 → 弹警示（"这条与你已确认的各期对不上"：可能标错、BGM 重、其实另一个人），人工听完再决定收不收。档案只进干净样本，一次手滑不会污染整个质心；
- **一对一互斥**（§4.4 已定）：一期内一个说话人只建议一个人物、一个人物只建议给一个说话人，贪心取最高分配对。

### 5.4 参考音闭环的两个纪律（推断，建议写进实现注释）

- **只收真人原声**：核对门确认后的说话人候选原声段（现状 /api/persons/ref 的行为）可以进库；**克隆 TTS 的输出永远不进参考音**——CosyVoice3 的克隆相似度 SS≈0.78（[CosyVoice 官方评测表](https://github.com/FunAudioLLM/CosyVoice)，02 底稿已收录），克隆音与真人的声纹相似度不低，混进注册库会造成"自我强化"的音色漂移；
- **来源可追溯**：embedding 缓存沿用 refs 的 `source` 语义（episode 记 bvid/part/spk），人物库已有的 D4 同分P拒绝规则照旧约束"收录"，embedding 只是派生缓存，删了能重算。

4. **换模型对照**（仅当第 3 步不过）：CAM++ 中文通用 ONNX 接入 `voiceid_bench.py --model campplus`，同样三组重跑，比 impostor 分离度；CAM++ 与注册/测试两例试听抽查（防"分数高但配错人"）；

内置模型路线：补 2 个视频的 diarization（GPU 各 ~1-2 分钟）+ 抽 embedding（几十段 × 5s 窗，秒级）；CAM++ 对照：onnxruntime CPU 单线程 RTF 0.013（论文口径），20 分钟音频约 16 秒。**总计一个下午内可跑完两轮。**

## ⑦ 风险与坑

| 风险 | 证据/机理 | 缓解 |
|---|---|---|
| **跨语言域差**（中文注册→英文测试） | VoxCeleb 训练系统在 CN-Celeb.E EER 3.75%→15.52%（[CN-Celeb 论文](https://arxiv.org/abs/2012.12468)） | §⑥C 组先量；不够换 CAM++ 中文通用；给圆脸补英文 ref（英文采访确认后收录，注意 D4 同分P规则只限克隆参考音，认人 embedding 无此限但仍建议跨期） |
| **BGM 污染** | 博主中文视频有 BGM（extract_refs.py 专门写了 BGM 启发式检测佐证）；embedding 模型训练有 MUSAN 音乐增广（CAM++ 论文）但非免疫 | ref 与测试段**保持同通道条件**（都用原声或都用分离人声轨）；重 BGM 期先过 Mel-Roformer 人声轨再抽 embedding（02 底稿分离组件已有） |
| **短语音段不可靠** | pyannote [issue #1961](https://github.com/pyannote/pyannote-audio/issues/1961)：短音频抽不出有效 embedding；WeSpeaker LM 说明适用 >3s | 按 SPK 聚合质心（默认做法天然规避）；逐段模式过滤 <3s |
| **克隆音与原声混淆** | CosyVoice3 SS≈0.78（官方评测口径），克隆音声纹分数不会低 | 克隆输出绝不入库；D 组探针量化；小样质检流程里明确"试听不等于验身" |
| **分身/聚类错误传导** | diarization 过分裂时同一人两个 SPK，各自质心都偏 | 认人只出建议；merge_into 决策（review_apply 已实现）先行，认人在合并语义之上只做建议层；margin 低→自动 unknown |
| **误配到不在库的人** | pyannote.ai 官方明说 voiceprint 可能匹配不在录音里的人 | THR+margin 双门；人物库小（现 2 人）时 impostor 池小、margin 门尤其重要；库扩大后定期用 §⑥脚本回归 |
| **分数口径混淆** | wespeaker CLI 的 confidence 是 (cos+1)/2 重映射（源码实测） | 项目内统一用原生 cosine，杜绝混用；引用外部分数先查口径 |
| **pyannote 版本漂移** | community-1 要求 pyannote>=4（config.yaml 实测），pyproject 还写 >=3.3 | §⑤.2 第 6 条顺手修正；`.venv-diar` 锁 4.0.7 不动 |
